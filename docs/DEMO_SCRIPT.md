# Demo script, target 2:55

## 0:00–0:18, the problem

“Small companies rarely know which person, device, approval, or recovery path has quietly become infrastructure. SAVE MY… makes that dependency visible before it becomes an incident.”

Open Diamond Apps. Keep the full `SAVE MY…` wordmark visible.

## 0:18–0:48, a hard rehearsal

Open **Founder and finance lead unavailable**.

“This is the stored scenario, separate from the company baseline. Two approvers disappear together. The deterministic engine traces the cascade, isolates the relevant graph, and finds five blocked workflows. It is not an AI score.”

Show the failure origins, hop labels, and five blocked workflows. Pan once horizontally to demonstrate the bounded camera.

## 0:48–1:24, ask the agent for complete options

Prompt the page-connected Site Tools agent:

> Read this company and the active founder-and-finance scenario. Validate the relevant dependency paths, then use the SAVE MY… Site Tools to propose three complete repair options. Compare their effort, restoration time, and residual risk. Do not accept anything for me.

“The agent uses native WebMCP. One tool call stages three bounded alternatives. The backend checks each option against the same graph engine. Every After view must reach zero blocked workflows.”

Show Options A, B, and C, then switch Before/After.

## 1:24–1:50, human authority and resolution

Choose Option B. Click **Adjust option**.

“I can rename proposed recovery items and retarget every fallback. SAVE MY… reruns the scenario and refuses an edit that would reopen a blocked workflow.”

Save an adjustment if desired, then click **Apply repair**.

“Only this visible human action changes the baseline. The other alternatives close automatically. The stored scenario is now marked Resolved, all critical workflows continue, and the unavailable people are shown as contained rather than as an active red cascade.”

## 1:50–2:38, build a company from description

Sign in locally, ask the Site Tools agent to create **Wow Project**, then prompt:

> Build a continuity map for a three-location beauty salon network. Include the founder, regional operations lead, location managers, front desk and stylist teams, three salons, booking and checkout workflows, opening and closing, same-day staff cover, stock restocking, booking/POS/client-record systems, product supplier, payout account, continuity playbook, incident channel, dual-custody keys, and backup mobile internet. Connect ownership, access, recovery, communication, and dependency paths. Stage the complete map for review; do not apply it.

“The agent turns one detailed description into one coherent proposal: 40 illustrated items, 78 labeled connections, eight critical workflows, and no orphan nodes. Stable references keep every relationship correct inside a single tool call.”

After `create_company` opens Wow Project, re-discover the active page's tools
and show the successful `create_company`/`get_workspace_summary` entries in the
call log before the blueprint call. If the tools are not ready, stop the agent
flow; do not demonstrate browser or computer control as a fallback.

Show **Baseline: 0 items / Draft: 40 new items**. Open **Adjust option** briefly, then apply.

After applying, ask for three materially different scenario drafts. Show the scenario library’s agent-attributed people, system/vendor, and compound rehearsals.

## 2:38–2:55, close

Show the resulting salon baseline and People & roles.

“The agent structures intent; the graph engine proves impact; the person remains the authority. MAP. BREAK. REPAIR. VERIFY. SAVE MY…”
